# talabflow · طَلَبْ‑فلو

[English](README.md)

**يحوّل محادثات تيليجرام إلى طلبات مُتابَعة: رقم مرجعي، ومسار حالات محكوم، وسجل تدقيق، وواجهة
API للموظفين، وتصدير إلى Excel. يعمل على خادمك أنت، ويمكن تجربته دون توكن بوت ودون إنترنت.**

![مقطع من مخرجات make demo](docs/demo.png)

<sub>مخرجات حقيقية للأمر `make demo`، مقتطفة (العلامة `⋮` تعني أسطرًا محذوفة). دون توكن بوت ودون شبكة.</sub>

## المشكلة التي يحلّها

المحلات وورشات الصيانة تستقبل الطلبات عبر المحادثة، ثم تضيع الطلبات بين الرسائل: لا رقم مرجعي،
ولا أحد يعرف حالة الطلب، ولا سجل لمن غيّر ماذا. talabflow يجعل كل محادثة طلبًا له رقم وحالة
وتاريخ.

## ما الذي يقدّمه

- محادثة استقبال منظّمة (آلة حالات) محفوظة لكل عميل، بالعربية أو الإنجليزية.
- أرقام مرجعية بأبجدية لا تلتبس حروفها.
- مسار حالات محكوم: لا ينتقل الطلب إلا عبر الانتقالات المسموحة، وكل تغيير يُسجَّل في سجل التدقيق.
- إشعار العميل عند تغيّر الحالة عبر transactional outbox مع إعادة المحاولة ومنع التكرار.
- واجهة REST للموظفين بمصادقة JWT وصلاحيات (مدير / موظف).
- إدارة حسابات الموظفين: تعطيل الحساب، تغيير الدور، وإعادة تعيين كلمة السر.
- تصدير الطلبات إلى XLSX و CSV.
- تحقّق صارم من رقم الهاتف: يُفحص الرقم وفق قواعد بلده هو (الطول والبادئات الموجودة فعلًا) عبر
  libphonenumber، فلا يُقبل رقم مثل `98765432109876` لمجرد أن عدد خاناته مناسب. يُخزَّن الرقم
  بصيغة واحدة (`+213555123456`)، ويُقبل بالأرقام العربية والهندية، ويعثر عليه البحث مهما كانت
  طريقة كتابته.
- زر «مشاركة رقم هاتفي» في تيليجرام: يرسل الرقم المسجَّل في حساب العميل نفسه، فيُحفظ الطلب
  بعلامة «رقم موثَّق» تظهر في الـ API والتصدير.

## التشغيل السريع

```bash
make setup
make demo
```

الأمر الثاني لا يحتاج توكن ولا شبكة: يطبّق ترحيلات قاعدة البيانات، وينشئ حسابات الموظفين، ويجري
محادثة كاملة، ثم يعرض مسار الطلب حتى التصدير.

## الجودة

- 489 اختبارًا آليًا دون أي اتصال بالشبكة، مع ruff و mypy نظيفين.
- CI يشغّل الترحيلات والاختبارات على SQLite وعلى PostgreSQL 16.

## الحدود، بصراحة

- مشروع محفظة أعمال: لا مستخدمون في بيئة إنتاج.
- على تيليجرام الحقيقي جُرِّبت يدويًا محادثة الاستقبال كاملة، وزر مشاركة الرقم، وإشعار تغيّر الحالة.
  حالات الخطأ (الحظر، تجاوز الحد، الانقطاع وسط المعالجة) مُختبَرة بخادم وهمي لا غير.
- PostgreSQL مُتحقَّق منه في CI فقط، ولم يُشغَّل في نشر فعلي.
- المحادثات الخاصة فقط: البوت يتجاهل رسائل المجموعات والقنوات عمدًا، حتى لا يُنشر فيها هاتف العميل وعنوانه.
- رقم الهاتف الصحيح ليس بالضرورة رقمًا يعمل: التحقق يثبت أن الرقم ممكن وفق قواعد بلده، لا أنه في
  الخدمة ولا أنه ملك العميل. الرقم «الموثَّق» هو فقط ما شاركه العميل بزر تيليجرام، ولا يوجد تحقق عبر SMS.
- اللغة تُحدَّد لكل نشر لا لكل عميل، ولا توجد لوحة تحكم ويب ولا دفع.
